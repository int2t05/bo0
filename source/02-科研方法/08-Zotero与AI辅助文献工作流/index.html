Zotero 与 AI 辅助文献工作流

用途：把检索、合法获取全文、阅读、AI 辅助、代码核验和备份连成可复查流程。
适用环境：本项目 Windows 10、Zotero 10.0.7、本地 zotero-cli / Zotero Local API。
核验日期：2026-11-06。AI 阅读主插件最终选用 LLM for Zotero，核验到的最新发行版为 v3.9.16（2026-11-02）。 状态：本轮同步工作流文档；文档选型不等于已在 Zotero 中核实安装版本或逐项配置。

建议结论

本项目以 Zotero 桌面端、官方浏览器 Connector、内置 PDF 阅读器、Jasminum 大纲功能、LLM for Zotero 和本机 zotero-cli / Local API 为核心。LLM for Zotero 负责 Zotero 阅读器内的论文问答、分段精读、多会话和引用回跳；read4all 负责为 Codex 等外部 AI 提供 MinerU 解析稿的转换与分段直读。AI 先读研究者选定的条目或全文，输出带 DOI、页码和章节定位的草稿；研究者核验后再写入 Zotero 或项目 Markdown。不要把“搜到记录”“有 PDF”“同步到另一台电脑”视为同一件事。

额外插件只解决明确痛点：Markdown 笔记双向整理可选 Better Notes；BibTeX / LaTeX 引用键需要时可选 Better BibTeX。PDF 翻译功能先在已选的 LLM for Zotero 中核验，不预先安装另一套 AI 侧栏或翻译插件。安装前先备份、核对 Zotero 10 兼容版本，一次只更新一个插件。Zotero 官方说明插件拥有对 Zotero 和电脑的完整访问权限，因此插件不是无风险的小工具。Zotero 插件说明

flowchart TD

    J --> K[更新证据矩阵、代码链接和检索式]
    K --> B

1. 文献检索：从问题到可复现的检索式

1.1 先确定这次搜索要回答什么

在检索前用几行写清：

  • 研究对象或场景：例如 refinery scheduling、crude oil scheduling、炼化生产调度。
  • 方法或机制：例如 evolutionary algorithm、surrogate-assisted optimization、LLM-assisted optimization。
  • 约束或困难：例如 dynamic、uncertainty、black-box、distributed、expensive evaluation。
  • 纳入范围：年份、语言、文献类型、是否要求真实工业场景、是否接受预印本。
  • 排除范围：仅概念相似但不研究目标任务的论文、无法确认来源的转载、无关应用案例。

本项目优先从博士推荐阅读清单中的核心条目、导师推荐文献和 3–5 篇可信综述起步。不要将 386 条索引当成 386 篇必读任务。

1.2 分层检索，而不是把所有词塞进一个长查询

先为每个概念列中英文、缩写、旧称和常见变体；概念内用 OR，概念间用 AND。将不同问题拆成多条检索式，避免“炼化场景 + 最新 LLM + 特定算法”过度相交而漏掉基础方法。

可从以下独立检索支线开始，再按结果调整：

("refinery scheduling" OR "crude oil scheduling" OR "refinery production scheduling")
("evolutionary algorithm" OR metaheuristic OR "genetic algorithm" OR "particle swarm")
("surrogate-assisted optimization" OR "expensive optimization" OR "data-driven optimization")
("large language model" OR LLM) AND (evolutionary OR optimization OR scheduling)

数据库的字段名、通配符、引号和邻近算符不完全相同；复制检索式后要按数据库语法调整，并保存实际执行版本。

1.3 数据源分工

目标 优先入口 使用边界
精确查出版记录 Web of Science、Scopus、IEEE Xplore、ACM Digital Library、出版社平台 以学校订阅可访问的平台为准；正式卷期、DOI 和版本回到出版社或会议页核对
扩展发现与引文追踪 Google Scholar、Semantic Scholar、OpenAlex、Crossref、ResearchRabbit 等 用于找候选和关联论文；不把排序、摘要或 AI 推荐当作质量判断
计算智能与机器学习 IEEE、ACM、Scopus / WoS、ACL Anthology、arXiv 预印本与正式发表版本分别登记，不用预印本冒充出版版
炼化、化工与中文研究 学校图书馆入口、CNKI、万方、出版社及机构仓储 记录访问日期、数据库、检索式和限制条件
代码与复现材料 论文正文、补充材料、作者主页、作者组织仓库、基准官方页 仓库必须能说明与论文/算法的对应关系；相似名字不足以证明对应

发现工具用于拓展覆盖；最终引文、结论和代码链接都要回到论文原文、出版方、机构仓储或作者维护的项目页核验。

1.4 用滚动检索补齐覆盖

  1. 从核心清单和综述中选种子论文，先读摘要、图表和结论，确认术语。
  2. 查种子论文的参考文献，找经典方法和早期问题定义。
  3. 查“被引用”文献，找后续改进、对比、反例和复现。
  4. 对近期论文设定提醒或按月补检；记录检索日期和数据库。
  5. 记录每条检索式、过滤条件、命中数、筛选结果及排除理由；正式检索任务直接把日志字段写入对应交付物。
  6. 检索范围不足时明确写出数据库、年份、语言、全文覆盖及搜索式边界。

这能支持“在给定范围内尚未找到直接研究”这样的有限结论，不能仅凭关键词没搜到就称“无人研究”。系统综述若成为正式研究产出，再另按 PRISMA 2020 和 PRISMA-S 规范设计与报告；PRISMA-S 是专门报告系统综述检索过程的扩展。当前训练期的滚动检索不应伪装成系统综述。

2. 采集与题录清理

  1. 从论文摘要页、出版记录页或图书馆目录页点 Zotero Connector，尽量保存完整题录；从搜索结果页批量保存时逐条检查识别到的条目。Zotero 官方也建议优先从题录页保存，元数据通常比直接保存 PDF 更完整。Adding Items to Zotero
  2. 检查标题、作者、年份、期刊/会议、卷期、DOI、URL 和文献类型。DOI 是首选核验键；无 DOI 时用标题、第一作者、年份交叉核实。
  3. 在 Zotero“重复条目”中比较后合并；预印本、接受稿和正式发表版若版本或内容有意义差异，作为独立记录并注明关系。
  4. 先放入“待筛选”集合，再决定是否进入课题主题集合。集合表达归属，标签用于跨集合的主题、方法和状态检索。
  5. 标签尽量采用小而稳定的词表，例如阅读状态、优先级、方法、应用场景。自动导入的出版社关键词可以保留，但不要把它们误作人工筛选结论。

本项目已有的具体附件修复经验、CLI 命令和逐条代码状态见文献检索与补全经验与全量文献索引。

3. PDF 获取：先判断失败类型，再选择入口

Zotero Connector 在很多网站可以保存题录及页面可访问的 PDF，或找到可公开获取的版本；这不意味着它能绕过付费墙。自动附加 PDF 的总开关在 Zotero 设置 → General → File Handling 中，官方文档显示默认启用。General 设置

3.1 建议获取顺序

  1. 从出版方文章页或学校图书馆记录页保存题录。
  2. 检查学校订阅是否可用：先在浏览器完成学校登录/代理登录，再回文章页保存；若使用代理，确认 Zotero Connector 的机构代理配置正常。Connector 机构代理说明
  3. 在 Zotero 对有 DOI/URL 且没有 PDF 子附件的题录运行“Find Full Text”（不同版本界面文字可能略有变化；Zotero 8 起使用这一菜单名称）。它会尝试已授权页面可访问的全文和开放获取版本；没有结果不代表论文不存在。Zotero 团队说明
  4. 再查出版方开放版本、作者主页、机构仓储、学科预印本仓储或图书馆文献传递。
  5. 手动下载后，把 PDF 拖到 Zotero 中对应的父条目上，使其成为子附件；拖入集合空白处通常会创建独立附件。确认 DOI、首页标题、作者和版本一致。添加附件 如果浏览器打开的是本机 file:// 下载路径，Connector 无法读取该本地路径；应直接把已下载文件拖入 Zotero。PDF 页面与本地文件说明
  6. 对每个高优先级附件检查文件能打开、页数合理、文字可选/可搜索、PDF 首页与父条目匹配。明确记录出版版、接受稿或预印本。

3.2 “没有 PDF”快速排查表

现象 常见原因 处理方法
只保存了网页或题录 当前页只提供元数据；Connector 未识别全文；PDF 自动附加被关闭 从文章/摘要页重新保存；检查 General 设置的 PDF 自动附加选项；查看 Connector 是否识别为文章题录
题录没有 DOI/URL，找全文选项不可用或无结果 搜索需要可用标识符，或题录字段不完整 先补全并核实 DOI/URL；再重试“Find Full Text”
条目已有附件记录但文件缺失，找全文选项不出现 Zotero 会把已有附件条目视为已有关联文件 先确认附件记录确实为空/文件缺失；再用 Zotero 的可恢复删除流程处理空附件条目，之后对父题录重试全文查找。Zotero 团队说明
浏览器能打开，Zotero 找不到 学校网页代理只在浏览器会话中生效；Zotero 桌面端不一定继承同一登录路径 在文章页用 Connector 保存；重新登录学校代理；查图书馆的 OpenURL / 文献传递入口。官方论坛说明基于代理网址的全文查找可能只拿到 OA 版本，浏览器 Connector 则可利用当前页面保存有权访问的文件。相关说明
下载到 PDF，但显示成单独文件 PDF 没挂到题录父条目 拖放到题录本身，或用“Add Attachment”；检查 DOI/元数据后再确认
有附件记录，另一台电脑却打不开 题录数据同步和附件文件同步是两套机制，附件同步可能未开或设为按需下载 检查 Storage / WebDAV 设置和附件下载选项，等文件同步完成后再在另一台设备验证。Zotero Storage 是官方推荐的附件同步方案；WebDAV 也可用，但依赖第三方服务正确运行。同步说明
Connector 显示 Zotero 未运行 Zotero 未启动，或 localhost 端口被代理、浏览器扩展、安全软件拦截 Zotero 打开时访问 http://127.0.0.1:23119/connector/ping；应看到 Zotero 正在运行。检查浏览器扩展对所有站点的权限、代理绕过 localhost、端口 23119 防火墙规则，再生成 Connector Debug ID。官方排查步骤
PDF 能打开，但 Zotero 搜不到其中内容 扫描件无文字层、OCR 文字质量差或全文索引未更新 用可信 OCR 工具处理后抽查文字层；在 Zotero 对附件执行 Reindex Item，必要时重建全文索引。重建前先确认 PDF 本身可复制且 OCR 质量合格。全文索引说明
附件内容与论文不一致 标题相似、预印本和出版版混淆，或自动化误挂 暂停使用该附件；核对首页、作者、DOI、年份和版本。确认误挂后通过 Zotero/CLI 可恢复流程移除，不直接改 SQLite 或清空回收站

访问边界： 无权限的付费全文应走学校订阅、图书馆文献传递、作者公开稿或开放仓储；不把未知镜像或自动绕过付费墙的脚本当作稳定方案。Zotero 的 OA 查找会将 DOI 发给 Zotero 服务检查开放版本；若不希望自动发送，可关闭自动附加相关 PDF 的设置，这也会关闭该自动附件功能。Zotero 隐私说明

排除代理和权限问题后仍无法下载时，确认 Zotero 已更新到当前稳定版：Zotero 10.0.6 修复过 Find Full Text 在部分网站失效及服务器错误时卡住的问题，10.0.7 修复过中断的 Zotero Storage 文件下载重试。版本历史

4. 插件组合：核心少、按需加

5. 阅读与 AI 辅助：AI 产出必须能回到原文

5.1 三层阅读

层次 阅读内容 产出
筛选 标题、摘要、问题、主要图表、结论 相关性、优先级、全文状态；低相关则说明排除理由
精读 问题定义、方法、数据、基线、指标、结果和局限 结构化论文阅读笔记，记录页码、章节、图表和公式
复现/批判 关键算法步骤、实验预算、消融、统计、代码和依赖 复现检查单、可能失效条件、最小复现实验或下一步问题

正式精读任务直接生成对应论文笔记交付物。区分“作者声称”“论文直接证据”“我的解释”“待核实”；重要结论注明印刷页码和 PDF 页码（两者不一致时都记）。

5.2 AI 适合做的事

  • 根据研究问题扩展同义词、缩写、可能的会议/期刊和检索式草案。
  • 对研究者选定的 PDF 提取问题、贡献、方法、变量、数据、基线、指标和限制。
  • 将多篇已核验的论文整理成对比表，列出方法差异、证据和分歧。
  • 解释公式、提出反例或复现问题；研究者回原文确认。
  • 检查代码链接是否来自作者或论文明确指向的项目。

AI 不应生成“看起来完整”的虚假 DOI、作者、实验结果或章节页码；也不应把摘要当作读过全文的证据。项目现有规则见科研诚信与 AI 协作。

5.3 推荐的提示模板

单篇抽取：

只依据我提供的这篇论文，不使用外部记忆补空缺。
请用表格列出：研究问题、作者声称的贡献、方法流程、数据/任务、基线、
评价指标、主要结果、局限、代码与数据链接。
每一条事实给出 Zotero key、PDF 页码、论文印刷页码（若不同）、章节/图表号。
把作者声称、论文直接证据、你的推断、未找到的内容分开。
找不到证据就写“原文未定位”，不要猜。

多篇比较：

只比较下列已提供的论文。先统一任务定义、数据集、基线、预算和指标；
这些条件不一致时不要直接按结果排名。
每个比较结论都给出论文 DOI/Zotero key 和页码或表图号。
分列：共识、方法差异、证据冲突、不可比条件、尚缺文献。

AI 生成后按引用逐项回到 PDF 检查。AI 表格是阅读辅助材料，不直接替代 Zotero 记录、原文摘录或研究者判断。

5.4 检索与代码链接也要做人工核验

  1. 让 AI 建议同义词和候选论文后，逐条用 DOI、出版页、机构仓储核对题名、作者、年份和版本。
  2. 找代码时先看论文正文、补充材料、作者主页和作者维护的仓库。仓库 README 应能说明论文/算法对应关系。
  3. 将链接分类为“论文代码”“作者实现”“基准/工具”“数据”“未找到可核验链接”。不要把参考文献里任意 GitHub 地址归给当前论文。
  4. 在索引中保留已核验的代码链接及来源关系；后续链接失效时，记录检查日期和替代的官方仓储。

5.5 MinerU 解析与 Markdown 辅助阅读

对双栏论文、公式或表格较多的文献，优先用 LLM for Zotero 内置 MinerU 为论文建立本机解析缓存，供论文对话和 Agent 按章节读取；Codex 工作流则用 read4all 的 convert_to_markdown 解析，再用 read_markdown 分段直读完整 Markdown。两套缓存相互独立，不把解析稿当作原 PDF。具体模型、传输边界、检查项和缓存位置见 MinerU 论文解析与 AI 阅读流程。

5.6 本项目的 Zotero AI 阅读主流程

LLM for Zotero 是本项目选定的 Zotero 内 AI 入口。建议先从 PDF 阅读器右侧的论文对话开始，问摘要、方法、结果或局限；后续问题继续沿用该论文上下文。精读时直接点名章节（例如 Abstract、Methods、Results），并查看任务进度里实际读取的章节与来源，再用可点击引用回到 PDF 核验。跨文比较时在不同 PDF 间切换，或在对话中附加其他文献。

需要并行处理多个问题时，可同时保留 Zotero 侧栏和 LLM for Zotero 独立窗口中的不同会话；v3.9.11 的发行说明注明 Codex 同时回答要求 Codex 0.156.1 或更新版本。侧聊用于临时追问，主会话保持原论文上下文。保存结论时先检查引用和页码，再写入 Zotero 笔记或导出 Markdown。

需要双语 PDF 排版时，先使用 Zotero 自带 Reading Mode 阅读原文；LLM for Zotero 的上游文档明确支持论文问答、章节精读、MinerU AI 缓存和会话窗口，但没有把全篇双语 PDF 阅读器列为功能。不能将“在聊天中翻译论文”当作已验证的原 PDF 对照阅读功能。插件当前版本、安装和 MinerU 开关须在 Zotero 中实测确认。

6. 本机自动化与数据可靠性

6.1 读取优先使用 Zotero CLI / Local API

本项目已有的 zotero-cli 命令和使用约定在补全文献经验文档。CLI 封装适合稳定重复的查询和覆盖检查；Local API 用于 CLI 不提供的本地读取/写入。

读取与覆盖审计可按下面的模式执行，尖括号中的集合键、条目键从当前库盘点获得：

zotero-cli --json get collection-items <COLLECTION_KEY> --detail full --limit 500
zotero-cli --json coverage --collection <COLLECTION_KEY> --limit 500
zotero-cli path <ITEM_KEY>

Zotero Local API 运行在本机 localhost:23119，可离线读取本地数据；读取请求不需认证。Zotero 10 的写入请求需要用户在 Zotero 中授权本地 API key，并在写请求中传入当前实例返回的 Zotero-Server-ID。不要转发或暴露 23119 端口，不能把本地 API key、服务器标识、模型 key 或账号密码写入项目文件。Local API 官方说明

本地 API 只说明 Zotero 数据读取发生在本机；如果 CLI 导出的全文随后交给云端 AI，论文文本仍会发送给对应 AI 服务。公开论文按服务条款选择处理方式；未公开稿件、工业数据、个人信息和凭证则按项目及机构要求限制上传。

6.2 每次批处理都生成可审阅的变更单

批量写入前，先生成一份候选变更清单，每行至少包括：

  • Zotero key、字段/附件、修改前值、建议值。
  • 修改原因、证据 URL/DOI、PDF 版本及身份核验结果。
  • 使用的脚本/CLI 版本、运行时间、批次编号。

先 dry-run 并抽查样本，再小批量写入，最后重新导出/读取 Zotero 验证。标签用追加语义保留已有信息；PDF 只有在题名、作者、DOI 和版本匹配后才挂到父条目。直接编辑 SQLite 或 storage 文件会绕开 Zotero 的数据完整性和回收站语义，禁止作为常规写入方法。

6.3 同步不是备份，不能把数据库放进 OneDrive

  • Zotero 数据同步负责条目、笔记、标签等；附件文件需要另配 Zotero Storage 或 WebDAV。
  • Zotero 官方建议使用 Zotero 同步访问多台电脑，并明确警告不要把正在使用的 Zotero 数据目录放入 Dropbox、Google Drive、OneDrive 等云盘同步目录，可能损坏 SQLite 数据库。多设备同步 · 云目录警告
  • 定期备份 Zotero 完整数据目录。手动复制前先完全退出 Zotero；备份范围包括 zotero.sqlite、storage 和其余数据目录内容。只导出 BibTeX/RIS 不是数据库备份。数据目录与备份
  • 至少保留一份离线或另一块磁盘上的版本化备份。恢复前先确认本机数据库、在线库和附件版本，避免误把旧库同步覆盖到服务器。
  • Zotero 版本升级及大插件更新前做一次可验证的备份。同步只保留当前状态，不能替代按时间恢复的备份。

6.4 检索和阅读的轻量验收

每周/每次专题迭代结束时核对：

  • 所有新记录有可定位题录（DOI 或题名/作者/年份）和来源。
  • 高优先级记录标出全文状态；有 PDF 的附件身份、父子关系正确。
  • 有 OCR 的扫描文件抽查文字层和页码，更新后可被 Zotero 索引。
  • 标签能回答“属于哪一主题、采用什么方法、现在读到哪一步”。
  • 精读笔记中的核心事实有原文页码/图表支持。
  • 每条代码链接都有对应关系说明；未确认的诚实标为未知。
  • 批处理前后记录数量、附件数量、大纲数量、标签和错误项变化可对账。
