优化问题：决策、目标与约束

先从一个具体场景开始。

实验室只有一台显微镜，周三 13:00 到 17:00 开放。A、B、C 三位学生各要连续用 1 小时：A 只能 13:00–15:00 来，B 只能 14:00–17:00 来，C 全天都行。管理员要排出时间表，让等得最久的那个人等得尽量短；三个人都得排上，设备同一时刻只能服务一人。

这段话里已经藏着一个优化问题的全部骨架：

  • 决策（decision）：谁在几点开始用。这是管理员能改的东西。
  • 目标（objective）：三人中最长的等待时间，越短越好。这是比较两个方案的标准。
  • 约束（constraint）：开放时段、个人可用时段、每次连续 1 小时、设备互斥。这是任何方案都不能违反的规则。

三者齐了，才叫优化问题：在允许的行动里挑一个，按说清楚的标准比好坏，同时不违反硬条件。少任何一件——比如没说清"比什么"——"找最优方案"就只是一句口号。

形式化记号

教材里通常把优化问题写成

\[ \min_{x}\ f(x)\quad \text{s.t.}\quad x\in X, \]

其中 \(x\) 是决策变量（把所有决定打包成一个向量），\(f\) 是目标函数（给每个 \(x\) 打一个分），\(X\) 是可行域（feasible region，满足全部约束的 \(x\) 的集合）。"s.t." 是 subject to 的缩写，意思是"满足以下条件"。这套记号贯穿后面所有章节。

对显微镜问题，\(x\) 就是三个开始时刻 \((t_A,t_B,t_C)\)，\(f\) 是三者等待时间的最大值，\(X\) 由时段和互斥规则圈定。

三个层次别混

同一个问题在三个层面上被谈论，混层是新手最常犯的错误：

层次 要回答的问题 显微镜预约
现实问题 谁做决定，想要什么？ 管理员排三个人的时段，缩短最长等待
数学模型 用什么变量、目标和约束描述？ 用开始时刻表示预约，用最大等待表示标准，用时段与互斥写限制
求解方法 怎么找到方案，能不能证明最优？ 枚举开始时刻、跑约束求解器、其他搜索方法

问题层说"要找什么"，模型层把决定和规则写成能检查的式子，方法层才谈怎么找。算法名字替代不了问题定义——说"我用遗传算法"没有回答"你在解什么问题"。

把可行安排都算一遍

这个问题小到可以手工枚举。按谁先用排序，等待时间按"开始时刻 − 最早可开始时刻"算（A、C 从 13:00 起算，B 从 14:00 起算）：

安排 A 等待 B 等待 C 等待 最长等待
A → B → C 0 0 2 2
A → C → B 0 1 1 1
C → A → B 1 1 0 1
B 先开始、或 C → B → A — — — 不可行：A 被挤出 13:00–15:00

六种排序只有三种排得下去，最优的最长等待是 1，且有两个并列解。这次枚举同时暴露了两条贯穿全课程的规则：

  • 可行先于更好。 三种排序根本不可行，比较好坏无从谈起。任何算法都要先回答"方案合法吗"，再回答"方案好吗"。
  • 最优解不一定唯一。 有并列时选哪个都行，或再拿别的标准（比如 A 最急）来挑。

描述问题的三问

拿到任何一段现实描述，先逼自己答这三句，答不出来说明还没读懂问题：

  1. 谁做决定，决定什么？（→ 决策变量）
  2. 拿什么标准比两个方案？（→ 目标函数）
  3. 哪些条件一个都不能破？（→ 约束）
flowchart LR
    A[现实情境] -->|辨认| D[决策]
    A -->|辨认| O[目标]
    A -->|辨认| C[约束]
    D & O & C --> M[数学模型 x, f, X]
    M --> S[求解方法]

箭头是理解顺序，不是工作流程：建模者来回走（写成模型后发现约束表达不了，回头重新理解情境）是常态。

三问落地之后，下一步是把它们正式写成数学模型，见线性规划模型。
